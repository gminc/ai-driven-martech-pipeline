# agent/：把查資料的工具交給 Gemini（Day 21）

把三個查 BigQuery 的工具宣告給 Gemini，讓它自己決定要不要查、查哪一個、參數填什麼，再拿同一批問題在「有工具」和「沒有工具」兩種情況各問一次

| 工具 | 讀哪張表 | 回答的問題 |
|---|---|---|
| `get_channel_attribution` | `mart_attribution`（Day 08） | 哪個通路分到多少訂單功勞 |
| `get_anomaly_diagnosis` | `diag_summary`、`mart_diagnosis`（Day 09） | 成效出過什麼狀況、原因是什麼 |
| `get_creative_feature_lift` | `mart_creative_lift`（Day 17） | 哪種廣告圖比較會賣 |

## 檔案

| 檔案 | 做什麼 | 會不會花錢 |
|---|---|---|
| `tools.py` | 三個工具的宣告（模型看得到的）與實作（真正查表的程式） | 不會 |
| `ask.py` | 6 個問題 × 有沒有工具，逐題問、記錄、對答案 | 會，先印最壞估價再問 |
| `check.sql` | 10 項流程檢查 | 不會 |
| `report.sql` | 五段報表：選對工具沒有、參數、回答原文、標準答案、Token 與費用 | 不會 |
| `run.sh` | 整個流程 | 會先問 |

## 工具守住的範圍

- SQL 寫死在 `tools.py`，模型只能填參數，不能自己寫 SQL
- 參數先過白名單（歸因算法、通路、指標）與日期格式檢查，多給的參數直接拒絕，檢查沒過不會碰到 BigQuery，只把錯誤訊息回給模型
- 值用查詢參數帶進 SQL，不做字串拼接，三個工具都只有 SELECT
- 每次查詢最多掃 100 MB，回給模型的結果最多 20 列
- 一個問題最多呼叫模型 4 次，每次送出前先數輸入 Token，超過 4,000 就不送

## 六個問題

| 題號 | 類型 | 問題 | 預期 |
|---|---|---|---|
| q1 | 一個工具 | 用時間衰減算，哪個通路功勞最多 | `get_channel_attribution`，`attribution_model = time_decay` |
| q2 | 一個工具 | meta 的成效出過哪些狀況 | `get_anomaly_diagnosis`，`channel = meta` |
| q3 | 一個工具 | 有人物的圖點擊率會不會比較高 | `get_creative_feature_lift`，`metric = ctr` |
| q4 | 兩個工具 | meta 兩種算法的功勞各多少，加上異常原因 | 歸因查兩次（`last_touch`、`time_decay`）加診斷一次 |
| q5 | 不需要查 | 時間衰減是什麼意思 | 不呼叫工具 |
| q6 | 查不到 | 上個月 TikTok 廣告花了多少 | 沒有工具答得了，看有沒有編出金額 |

標準答案在對答案時另外寫 SQL 直接查表，不經過工具的程式

## 實跑結果（2026-10-05）

| 情況 | 選對工具 | 參數正確 | 回答 | 呼叫模型 | 費用（新台幣） |
|---|---|---|---|---|---|
| 有工具 | 需要查的 4 題都對 | 4 題都對 | 數字與原因全部對得上資料表，不需要查的沒有查，查不到的回答沒有資料 | 10 次 | 0.40 元 |
| 沒有工具 | 不適用 | 不適用 | 1 題說查不到，4 題給了資料表裡沒有的內容，其中 2 題編出具體數字 | 6 次 | 0.48 元 |

- 10 項檢查全部通過，12 題次合計約新台幣 0.87 元（事前印出的最壞金額 10.25 元、預期 0.86 元）
- q4 在同一輪提出三個呼叫（歸因兩次、診斷一次），所以也只呼叫了模型兩次
- 三個工具的定義約 600 個 Token，每次呼叫模型都會算進輸入
- 沒有工具時思考 Token 用了 3,364 個，有工具時 907 個，所以這一輪沒有工具反而比較貴

## 限制

- 每題每種情況只問一次，溫度設 0，換一次問法或再問一次結果可能不同
- 「講到幾個」是比對回答裡有沒有出現標準答案的數字或原因，回答原文在報表第 3 段，要自己讀過才算數
- 單輪問答，沒有多輪對話，聊天式的助理在 Day 22
- 單價用官方定價頁 gemini-3.6-flash global 端點的價格（每百萬 Token 輸入 0.75、輸出 3.75 美元），實際以帳單為準
